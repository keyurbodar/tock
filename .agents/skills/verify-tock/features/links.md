# Links

Follows T3Code's MarkdownExternalLink (favicon glued to the first characters, long words break, short ones stay whole) with the TDS PxChips "Links" look.

- Every markdown link goes through `Reference` in `apps/web/src/chat/markdown.tsx`: `tock-file:` becomes a file chip, `tock-thread:` a thread chip, http(s) an external link, anything else plain text.
- Every chip (link, file, chat, skill, command; bubble and composer) is one `Chip` in chat/chip.tsx (the composer's TipTap token renders the same markup), as t3code's ContextChip: an inline-flex row aligned on the baseline, a 14px `.tds-chip-slot` whose bottom edge is the label's baseline, a label that clips with an ellipsis. The box is the 22px token, centred on the line by padding and cancelled by negative margins, so it never grows the line. A chip that navigates underlines its label on hover (150ms, t3code's transition-colors).
- A link whose text is the address itself (`isAddressLabel`) is that chip with the favicon in its slot (`a[data-link=web][data-shape=chip]`); any other `[words](url)` stays words (`a.tds-link[data-shape=words]`) with a 14px inline-block favicon on the baseline and a solid underline on hover.
- The favicon box is reserved before the bytes arrive; the globe shows, then the favicon fades in over it through `@tock/ui/motion`; on error the globe stays and the box keeps the failed URL in `data-icon-failed`. Bytes come from `/api/link/icon?host=`, never from the site.
- One shared hover card (`ChipCards` in chat/chip-card.tsx, `.tds-chip-card` plus `.tds-link-card`/`.tds-thread-card`/`.tds-file-card`/`.tds-skill-card`), as t3code's SharedTooltipProvider: triggers are found by delegation on `[data-card]`; it opens after a 600ms rest (`motion.chip-card.open`), swaps at once while one is open or within 400ms of one closing (`reopen`), closes after a 100ms grace (`grace`) so the pointer can travel into it, opens at once on keyboard focus, and a press, a scroll or Escape dismisses it. It sits above the trigger, centred, 4px off, kept 5px inside the viewport (below when there's no room), and enters from .98 with a fade at its trigger-side origin (`motion.enter.card`). Link cards show favicon, title, site, URL; chat cards title, preview, count; file cards name and type; skill cards name and description (`/api/skills`).
- Skills: `@` lists installed skills after chats; a skill token sends `[name](tock-skill:name)`, which renders as a skill chip.
- Right-click opens the shared link menu (Open Link, Copy Link); Copy confirms with a "Link copied" toast.
- Hover styles sit behind `(hover: hover) and (pointer: fine)`, which headless Chrome reports false, so journeys can't assert them.

Against a deploy (non-localhost `TOCK_URL`), or locally with `TOCK_REAL_LINKS=1`, the link journeys clear the fixture cookie and use real pages (github.com/keyurbodar/tock, MDN for the linked words), checking titles loosely. When a favicon doesn't land they report each icon's proxy status, content type, `naturalWidth` and computed opacity.

Journeys: `links`, `linkchips`, `chipcards` (link, chat and skill chips share the slot, baseline and 22px box; the card waits ~600ms, swaps at once between chips, enters from .98; the @ menu lists skills and a skill token opens its card) (chip and words, 14px icon on the baseline via a Range, no layout shift while favicons load, card title and site, composer chip card).
